# School calendar subscription

On the existing Calendar page, paste an HTTPS (or webcal) iCalendar subscription link into the School calendar link field next to the shared Sync control. Press Sync. A successful sync opens the existing /calendar page automatically, showing school events alongside assignments; if the selected month is empty, it opens a month containing imported events. The link field and calendar sync control appear only on the Calendar page; no new page, preview dialog, or subscription-management controls are added.

Calendar Sync refreshes the pasted feed. Home’s Sync classes button retains its existing D2L/To-do behavior. Clearing the link does not delete already synced events. A successful refresh replaces the single cached feed atomically, updating changed events and removing cancelled/removed ones without changing assignments, scores, notes or D2L data. A failure preserves the previous calendar.

The link is remembered only in this browser under classsync-school-calendar-url-v1. It is sent to the ClassSync server only when Sync is pressed, is never returned in API results, and is excluded from workspace cloud saves and JSON exports. The parsed events themselves are included in workspace saves/backups. On another browser, paste the subscription link again to refresh.

Workspace version 3 adds a nullable schoolCalendar with cached events, sync time, time zone and supported date range. v1/v2 data migrates through validation; the original v1/v2 localStorage keys remain available for recovery. The new browser key is classsync-workspace-v3. The existing JSONB cloud table needs no SQL change. Older app versions reject v3 rather than silently dropping calendar data.

Sync caches events from the previous 31 days through the next 366 days, interpreted in the student's browser time zone. It supports VEVENT records, all-day exclusive DTEND, floating/UTC/IANA/embedded VTIMEZONE dates, daily-or-less-frequent recurrence, exclusions, moved occurrences and cancellations. It does not turn events into graded assignments. RRULE range changes (THISANDFUTURE), recurrence more frequent than daily, feeds over 1 MB, more than 1,000 source records or 500 expanded events, and expansions exceeding 20,000 iterations fail visibly. Only one feed is cached. Scheduled/background refresh is not implemented: press the existing Sync button to fetch updates.

The Node server endpoint is POST /api/calendar/sync. It requires a same-origin request, bounds body size, and uses a per-process request limit. HTTPS is required, redirects are limited and revalidated, private/reserved destinations are blocked, DNS results must all be public, and the socket is pinned to a validated IP while retaining the original TLS server name. No school credentials, cookies or browser session are forwarded. A private bearer URL can work; a link to a school login page cannot.

Tests cover dates and midnight boundaries, daylight-saving recurrence, exclusions and exceptions, duplicate updates, cancellation-only records, migration/backup round trips, private URL exclusion, private-network blocks, mixed DNS answers, and non-leaking error responses. The student-provided school feed was tested locally and its real events rendered on /calendar. Private feed URLs are not recorded in this guide or test fixtures.
